# 简历竞争力诊断

## 核心原则

- 先确定求职目标，再评价简历。脱离岗位、职级、城市和薪资预期，不下绝对化的“有竞争力”或“无竞争力”结论。
- 把“简历是否拿到面试”作为首要问题，不把排版、措辞或 STAR 格式当作竞争力本身。
- 只依据用户提供的简历、项目补充材料、JD 和投递反馈作事实判断。明确区分原文事实、合理推断、信息缺口，不编造经历、指标或能力。
- 把“简历未体现”“证据不足”“实际能力待提升”分开表述。仅凭一份简历不断言候选人真实能力不足。
- 默认使用“强 / 中 / 弱 / 信息不足”等定性判断。仅在用户要求量化且证据足够时评分，并说明评分口径，避免伪精确。

## 收集输入

优先获取以下材料：

1. 完整简历或项目经历原文。
2. 目标岗位与目标职级。
3. 目标城市、薪资预期；有具体 JD 时一并读取。
4. 可选的投递渠道、投递数量、回复数量、面试数量和所处阶段。

缺少目标岗位或职级时，先询问这两项；城市或薪资会显著影响判断时再询问。用户只要求快速初筛时，可基于明确列出的假设做条件式诊断，但不得给出脱离目标的市场竞争力定论。

## 执行流程

### 1. 建立目标基准

提取目标岗位、职级、城市、薪资及 JD 中的关键要求，概括该目标通常需要证明的能力。区分：

- JD 明示要求；
- 基于岗位常识作出的推断；
- 尚未确认的信息。

不得仅凭工作年限直接认定职级或能力水平。

### 2. 建立证据清单

逐项记录简历中的关键能力主张及其支撑材料。优先引用或概括对应原文，检查是否包含：

- 项目或业务背景；
- 规模、复杂度或约束；
- 真正的难点；
- 解决方案及其深度；
- 候选人本人的具体贡献；
- 可验证的结果或影响。

没有量化指标不等于没有价值；可使用范围、责任、复杂度、质量改善或业务影响等非数字化证据。不得为了“看起来有成果”而虚构数字。

### 3. 诊断基础竞争力

判断简历是否体现目标职级应有的能力，并给出“强 / 中 / 弱 / 信息不足”、依据和差距。

对于工程岗位，可参考以下层级特征，但以实际 JD 为准：

- 初级：能否完成可靠的功能研发与交付；
- 中级：能否独立分析并解决问题、承担完整模块；
- 高级：能否处理系统设计、性能优化、高可用、复杂业务问题或跨团队协作。

对于非工程岗位，从 JD 和行业标准中提炼对应层级要求，不机械套用工程示例。重点检查“多年经验”是否只重复了低复杂度工作，以及目标职级要求是否在核心项目中得到证明。

### 4. 诊断差异化竞争力

比较同层级、同岗位候选人的常见基础要求，寻找既有目标相关性又有证据支撑的优势，例如：

- 与目标岗位直接相关的大规模或高复杂度实践；
- 稀缺且可迁移的行业、领域或业务积累；
- 有实际落地和结果支撑的前沿技术或复杂工程经验；
- 能覆盖目标岗位关键痛点的复合能力。

使用以下三个问题筛选差异化：

1. 大多数同层级候选人是否也具备？
2. 它是否直接关系到目标岗位的成功？
3. 简历中的项目或成果能否证明？

常见技术栈、工具名称或抽象自我评价不能单独构成差异化。没有足够信息时，列出“可进一步挖掘的差异点”，不要强行认定优势。

### 5. 诊断能力证明

选择最相关的 2–4 个核心项目，逐项审查规模、难点、方案深度、个人贡献和结果。重点判断“用技术解决了多难的问题”，而不是罗列了多少技术。

对每个项目给出：

- 已证明的能力；
- 尚未证明的主张；
- 最关键的证据缺口；
- 最值得补充的问题。

区分“使用了某技术”和“能说明为何使用、如何取舍、解决了什么问题、产生了什么结果”。

### 6. 区分问题类型

允许多种问题并存，分别给出判断依据，不把一切都归结为简历写作。

| 类型 | 判断条件 | 优先动作 |
| --- | --- | --- |
| 表达问题 | 原始材料中已有能力和成果，但简历未清楚呈现目标相关信息 | 重组重点，补足背景、难点、贡献和结果；只改写已知事实 |
| 证据问题 | 简历声称具备优势，但项目和成果不足以支撑 | 追问细节、补充真实证据；无法补充时降低或删除主张 |
| 能力问题 | 结合补充材料后，目标所需能力仍有明确缺口 | 制定实践、项目或学习路径，不用措辞掩盖能力缺口 |
| 定位问题 | 现有竞争力与目标岗位、职级、城市或薪资预期明显错位 | 调整目标或建立过渡路径，再决定简历策略 |

只有存在其他材料或简历内部证据时，才判定“有能力但没写好”。信息不足时使用“待验证”，不要在证据问题与能力问题之间武断二选一。

### 7. 制定分类型行动方案

按对获得面试机会的影响排序，使用 P0 / P1 / P2 标记优先级。每项建议包含动作、对应问题、所需真实材料和预期改善点。

- 定位问题：优先调整岗位、职级、城市或薪资组合，或明确过渡目标。
- 能力问题：优先安排能形成真实证据的实践，不把课程或技术名直接写成项目成果。
- 证据问题：优先通过访谈式提问补齐事实；未知内容使用“[需补充：具体规模/个人贡献/结果]”等占位，不自行填写。
- 表达问题：最后调整结构、顺序和措辞，使目标相关证据更显眼。

除非用户明确要求，不在诊断后自动重写整份简历；先给出最值得修改的段落或示例即可。

### 8. 用投递反馈验证

有真实投递数据时，将诊断视为待验证假设：

- 按相同或相近目标岗位、渠道和时间窗口记录投递、回复、面试及后续阶段；
- 有条件时按“投递 → 回复 → 面试”观察变化，不只记录总投递量；
- 每轮只改变一个主要变量，例如目标定位、核心项目呈现或投递渠道；
- 对比调整前后的自身数据，不编造通用回复率或面试率基准；
- 同时考虑岗位供给、渠道、时机和匹配度，避免把全部结果归因于简历；
- 已能稳定获得面试但后续受阻时，将简历问题与面试、能力或岗位匹配问题分开分析。

## 默认输出结构

根据材料完整度裁剪篇幅，但保留以下核心部分：

```markdown
## 结论
（一句话条件式结论：针对什么目标，当前主要短板是什么。）

## 目标与判断口径
（岗位、职级、城市、薪资、JD 来源及必要假设。）

## 三维诊断
| 维度 | 判断 | 关键依据 | 主要差距 |
| --- | --- | --- | --- |
| 基础竞争力 | | | |
| 差异化竞争力 | | | |
| 能力证明 | | | |

## 核心项目证据审查
（列出最相关项目：已证明能力、证据缺口、需补充问题。）

## 问题分类与优先级
| 优先级 | 类型 | 判断依据 | 建议动作 |
| --- | --- | --- | --- |

## 待补充信息
（只问会改变判断或能直接改善简历的问题。）

## 投递验证方案
（有反馈时复盘；无反馈时给出下一轮验证方法。）
```

## 质量检查

输出前确认：

- 结论是否绑定明确目标或清楚标注假设；
- 每项优势是否有对应项目或成果证据；
- 是否把“未体现”误写成“不具备”；
- 是否将常见技能堆砌误当成差异化；
- 是否区分了表达、证据、能力和定位问题；
- 建议是否对应该类型，而非一律润色简历；
- 是否存在编造的数字、经历、市场基准或确定性承诺。
